## 1. Базовая настройка репозитория (уже выполнено)

Проверка SSH-подключения к GitHub:
```bash
ssh -T git@github.com
```

Проверка настроенных удалённых репозиториев (remotes):
```bash
git remote -v
```
> Ожидаемый вывод:
> * `origin` → `git@github.com:VladTer06081963/lapian-notes.git` (ваш личный форк)
> * `upstream` → `git@github.com:bkingfilm/lapian-notes.git` (оригинал автора)

Если когда-либо потребуется настроить их заново:
```bash
# Переименовать origin в upstream (если был только оригинал)
git remote rename origin upstream

# Добавить ваш форк под именем origin
git remote add origin git@github.com:VladTer06081963/lapian-notes.git
```

## 2. Управление ветками

Посмотреть список локальных и удалённых веток:
```bash
git branch -a
```

Переключиться на основную рабочую ветку `dev`:
```bash
git checkout dev
```

Создать новую ветку под конкретную задачу/фичу:
```bash
git checkout -b feature/название-задачи
```

Опубликовать новую ветку в ваш GitHub с привязкой отслеживания:
```bash
git push -u origin feature/название-задачи
```

Удалить локальную ветку (после завершения работы):
```bash
git branch -d feature/название-задачи
```

## 3. Ежедневный цикл разработки (Edit → Check → Commit → Push)

### Шаг 1: Проверка статуса и изменений
```bash
# Проверить, какие файлы изменены или ещё не отслеживаются
git status

# Просмотреть детальный дифф незакоммиченных изменений
git diff
```

### Шаг 2: Проверка проекта перед коммитом
Перед отправкой изменений рекомендуется убедиться, что код собирается и проходит тесты:
```bash
# Полная проверка (тесты + i18n + линтер + сборка)
npm run check
```

### Шаг 3: Добавление изменений в индекс
```bash
# Добавить конкретный файл:
git add путь/к/файлу.ext

# Или добавить все изменённые файлы проекта:
git add .
```

### Шаг 4: Создание коммита
```bash
git commit -m "краткое понятное описание сделанного"
```
*(Примеры: `feat: добавить поддержку русского языка`, `fix: исправить парсинг таймкода`, `docs: обновить changelog`)*.

### Шаг 5: Отправка коммитов в ваш репозиторий на GitHub
```bash
# Если ветка уже привязана (как наша dev):
git push
```

## 4. Синхронизация с оригиналом (`upstream` от автора)

Когда автор проекта выпускает обновления или исправления, чтобы подтянуть их в вашу ветку `dev`:

```bash
# 1. Загрузить все свежие коммиты и ветки из оригинального репозитория
git fetch upstream

# 2. Убедиться, что вы находитесь в своей ветке dev
git checkout dev

# 3. Влить изменения из главной ветки автора
git merge upstream/main

# 4. Отправить обновлённое состояние в свой GitHub
git push origin dev
```

## 5. Откат и отмена изменений (в случае ошибки)

Сбросить незакоммиченные изменения в конкретном файле:
```bash
git restore путь/к/файлу.ext
```

Отменить индексацию файла (если сделали `git add`, но передумали коммитить):
```bash
git restore --staged путь/к/файлу.ext
```

Временно спрятать текущие изменения без коммита (stash):
```bash
# Спрятать
git stash

# Вернуть обратно
git stash pop
```

Посмотреть историю коммитов:
```bash
git log --oneline -n 10
```
